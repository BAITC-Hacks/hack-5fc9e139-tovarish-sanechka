# Граф денег · HackAlem

```sh
docker compose up -d --build --wait --wait-timeout 360
```

Откройте **http://localhost:8080** в браузере. Нужны только Docker Engine
с Docker Compose v2 и браузер. Python, Node.js, uv и `.env` на хосте не нужны.
Первая сборка скачивает образы и пакеты; время зависит от сети.
При каждом старте контейнер автоматически рассчитывает результаты из Parquet
и открывает интерфейс только после успешной проверки.

Обычный `docker compose up -d --build` также работает: дождитесь статуса
`healthy` в `docker compose ps` перед открытием страницы.

```sh
docker compose ps
docker compose logs -f app
docker compose down
```

Последняя команда останавливает приложение. Если порт 8080 занят, остановите
занимающее его приложение либо замените только левый порт в compose.yaml,
например `127.0.0.1:8081:8080`, и откройте http://localhost:8081.
После изменения Parquet или config повторите команду с `--build`.
После сборки расчёт и интерфейс работают без внешних API, CDN и интернета.

## Что делает приложение

Помогает выбрать узел для проверки и объяснить наблюдаемое поведение.
**Роли — гипотезы, не утверждения о виновности.** Размеченных ролей нет;
скоры не являются вероятностями нарушения.

- Таблица всех 2 248 узлов с приоритетами, сортировкой и фильтрами.
- Выборка «Новые точки консолидации»: клиенты вне исходного списка с
  признаками консолидации, включая альтернативную роль. Сохраняются общий
  приоритет, глобальные номера и основная гипотеза каждого узла.
- Поиск любого полного gid независимо от фильтров, включая 19 изолятов.
- Поиск общих новых узлов от 2–5 исходных gid: пересечение направленной
  достижимости, ранжированный список и кратчайший наблюдаемый путь от каждого
  выбранного исходного узла с суммами и числом операций на рёбрах.
- Карточка: гипотеза, числовые основания, входящие/исходящие, альтернативные
  роли, место и вклады в приоритет, ограничения, кластер и следующий запрос данных.
- Направленный граф окружения, кластера или кратчайшего наблюдаемого пути от
  исходного узла. Путь перечисляет полные gid, суммы и число операций по рёбрам.
  У путей от seed и в поиске общих узлов проверяется последовательность дат:
  согласована, требует неизвестного порядка внутри дня или противоречит датам.
  Выбранные даты операций показаны отдельно от месячных сумм рёбер.
  Для окружения и кластера по умолчанию максимум 80 узлов; скрытые элементы
  посчитаны, доступна кнопка «Показать всё».
- Таблица устойчивости крупнейшей компоненты: исключение топ‑5/10/20 узлов
  с контролем по степени и 100 случайным выборкам.
- Полный список переводов выбранного узла и скачивание трёх CSV.

Результаты внутри контейнера находятся в `/app/out`:

| Файл | Содержание |
|---|---|
| nodes_roles.csv | Все узлы, role, role_score, cluster_id, priority_score, evidence, seed_path_gids, next_check и признаки |
| clusters.csv | Размер, число seed, внутренний оборот, top_gids и гипотеза по внешним потокам и ролям |
| top_nodes.csv | Все узлы по убыванию приоритета, rank от 1, числовое объяснение |
| analysis.json | Те же результаты, связи с датами операций, сценарии устойчивости и метаданные для UI; schema_version=2 |

В CSV gid хранится десятичным int64; импортируйте столбец как текст в
электронные таблицы, чтобы не потерять точность. В JSON все gid — строки.
`top_gids` и `seed_path_gids` в CSV — JSON-массивы строк. Неопределённые дополнительные отношения
пусты в CSV и равны null в JSON; обязательные поля всегда заполнены.
Готовые копии трёх CSV и [слайд решения](submission/overview.svg) лежат в
[`submission/`](submission/) для просмотра без запуска. При пересчёте исходных
данных актуальны файлы из `/app/out`.

Для сохранения результатов на хост достаточно ссылок в UI или:

```sh
docker compose cp app:/app/out/nodes_roles.csv ./nodes_roles.csv
docker compose cp app:/app/out/clusters.csv ./clusters.csv
docker compose cp app:/app/out/top_nodes.csv ./top_nodes.csv
```

## Аналитика

Развивается исходный `case/starter/starter.py`: валидация → полный DiGraph →
признаки → Louvain → правила ролей → приоритеты → проверка → CSV/JSON.
Браузер использует готовые роли и приоритеты; для интерактивного поиска
общих узлов он обходит уже загруженные направленные рёбра. БД, очереди и
обязательного LLM нет.
Путь выбирается по направленным рёбрам детерминированно: минимум шагов,
затем меньший gid исходного узла и лексикографически меньший путь. Сам seed
не считается своим источником. Это связь в графе, а не трассировка одной
денежной суммы по датам.

В поиске общих узлов вводятся 2–5 различных gid из 81 исходного клиента.
Результат содержит только не-seed узлы, достижимые от каждого введённого
gid, в порядке уже рассчитанного приоритета. Для каждого источника отдельно
строится кратчайший путь; при равной длине следующий gid выбирается по
возрастанию. Пустой результат означает отсутствие общего узла **в этой
выборке**. Пересечение путей не подтверждает происхождение средств и не
меняет роль или приоритет узла.

Хронология проверяется для каждого показанного пути. Сначала ищется строго
возрастающая последовательность дат операций, затем — неубывающая. Если
возможна только вторая, порядок внутри дня неизвестен. Если невозможны обе,
показан первый конфликтующий шаг; другой маршрут может существовать.
Согласованные даты не подтверждают движение одной суммы. Альтернативные
маршруты по датам автоматически не ищутся. JSON версии 2 содержит для каждого
ребра непустой отсортированный список уникальных `dates` (`YYYY-MM-DD`);
при обновлении приложения нужно пересчитать результаты. Формат CSV сохранён.

Пороги и веса — в [config.toml](config.toml). Обоснование распределениями,
точные формулы и чувствительность — в [описании аналитики](docs/ANALYTICS.md)
и [профиле данных](docs/DATA_PROFILE.md).

| Гипотеза | Основные условия |
|---|---|
| Консолидация | ≥3 плательщиков, ≥2 достижимых seed, крупнейший плательщик ≤80% |
| Распределение | ≥5 получателей, крупнейший получатель ≤80% |
| Транзит | Не seed; вход и выход ≥164 528 ₸; out/in 0,7–1,4; близость дат ≥69% |
| Удержание | Не seed и не граница depth=4; вход ≥164 528 ₸; out/in ≤10% |
| Связующий узел | ≥9 достижимых seed, ≥2 внешних соседних кластеров, betweenness ≥0,0001553 |
| Недостаточно оснований | Остальные правила не сработали |

Выбирается максимальный допустимый score, конкуренция снижает role_score.
Равенства разрешаются порядком в config. Приоритет отдельно сочетает охват
seed (35%), структуру (40%) и оборот (25%), с логарифмической нормализацией.
Равный приоритет сортируется по числовому gid.

Louvain использует сумму встречных потоков на ненаправленной проекции,
без самопереводов, seed=42 и resolution=1. Изоляты — отдельные кластеры.
В оборотах самопереводы сохранены, в числе контрагентов себя не считаем.
Порядок узлов/рёбер и нумерация сообществ фиксированы.

## Ограничения

Выборка содержит только внутрибанковские операции ≥5 000 ₸ за июль 2026,
полученные обходом исходящих на четыре колена. Вход seed неполон; дальнейшие
переводы 444 граничных узлов неизвестны. Поэтому отсутствие выхода не
доказывает удержание. Даже terminal относится только к наблюдаемой выборке.
Достижимость от seed не доказывает происхождение денег; близость дат не
трассирует те же средства. Путь по агрегированным рёбрам также не доказывает
движение одних и тех же денег. Обороты повторно считают деньги вдоль цепочек.
97 повторяющихся строк операций сохранены: нет оснований удалять их.

При повышении исследованных порогов на 10% меняются 83 роли (3,69%),
включая всех пяти coordinator. Эта роль чувствительна к границам.
Нет внешнего обогащения, атрибутов клиентов и оценки accuracy без разметки.

## Разработка и проверки

Проверяемое окружение: Python 3.12.13, Node.js 24.20.0, uv 0.11.21.
Python-зависимости в uv.lock, frontend — в package-lock.json; базовые
Docker-образы зафиксированы версией и digest. Сервер работает от uid 10001.
Healthcheck проверяет доступность UI, JSON и CSV и хеши текущего запуска.
Ошибка данных завершает процесс с ненулевым кодом, автоматических рестартов нет.

Дополнительный запуск без Docker:

```sh
uv sync --locked
npm --prefix web ci
npm --prefix web run build
uv run python run.py --data case/data --out out --serve
```

Без `--serve` — только расчёт, UI не требуется. Доступны `--config`, `--ui`,
`--host` (по умолчанию 127.0.0.1), `--port` (8080). Каталог результата нельзя
пересчитывать, пока его обслуживает сервер. Исходные Parquet не изменяются.

```sh
uv run pytest -q
npm --prefix web run build
npm --prefix web exec playwright install chromium
npm --prefix web run test:e2e
```

Для E2E приложение уже должно работать на 127.0.0.1:8080. Другой адрес —
`APP_URL`; установленный Chromium можно указать через `CHROMIUM_PATH`.
Браузеры Playwright нужны только разработчику, не для Compose-запуска.

[Результаты проверок поставки](docs/VERIFICATION.md): полный расчёт,

## Масштаб до миллиона узлов

NetworkX, точная betweenness и полный JSON в браузере перестанут подходить.
Агрегировать Parquet пакетами (Arrow/DuckDB), хранить компактный граф CSR
или использовать igraph; betweenness оценивать выборкой, достижимость seed —
битовыми наборами/пакетными обходами. Подбирать метод сообществ на ресурсах
целевого окружения. Выдавать через API только страницу списка и локальный
подграф, с серверными фильтрами и лимитами. Сохранять числовые основания и
проверки целостности на каждом этапе. Сейчас эта инфраструктура не требуется.

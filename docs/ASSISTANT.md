# Ассистент аналитика через Alem

Ассистент распознаёт намерение в вопросе. Роли, приоритеты, маршруты и
объяснения вычисляет приложение. Свободного ответа модели, агентного цикла,
внешнего обогащения и изменения решений аналитика нет.

## Настройка

Сервер читает `ALEM_API_KEY`, `ALEM_CHAT_URL`, `ALEM_MODEL` из окружения;
отсутствующие переменные нативного запуска берёт из корневого `.env`.
Пустая переменная окружения также имеет приоритет. Значения разбираются
как данные, без исполнения shell и подстановок. Перезапуск применяет настройки.
Compose явно передаёт только три переменные Alem; `.env` не копируется в image.

Необходимы непустые `ALEM_API_KEY`, `ALEM_CHAT_URL` и `ALEM_MODEL`;
значений URL и модели по умолчанию нет. Без файла `.env` и переменных окружения,
а также при отсутствии любой из трёх настроек AI отключён. Основной расчёт,
граф, ручные запросы, досье и выгрузки остаются доступны. Для отключения
уже настроенного AI без изменения файла можно передать пустые значения:

```sh
ALEM_API_KEY= ALEM_CHAT_URL= ALEM_MODEL= docker compose up -d --force-recreate --wait --wait-timeout 360
```

Команда пересоздаёт контейнер и заново рассчитывает данные. Чтобы снова
применить настройки из `.env`, выполните её без трёх присваиваний.
Нативный загрузчик `.env` не поддерживает shell-подстановки; Compose
разбирает файл своим механизмом. Ошибка чтения настроек, перехваченная
`run.py`, не останавливает приложение; ошибка разбора файла самим Compose
может остановить запуск ещё до Python.

[Документация Alem](https://doc.alem.ai/services/gptoos.html) описывает Bearer
авторизацию и модель `gpt-oss`. URL в примерах отличается наличием `/v1`,
поэтому задаётся полный рабочий адрес. Поддержка tool calling не предполагается:
используется обычный Chat Completions с JSON в текстовом ответе. Перенаправления
не выполняются, чтобы не пересылать ключ другому endpoint.

## Контракт

`GET /api/assistant/status` возвращает `{enabled, message}`. Это наличие
корректной конфигурации, а не live-probe провайдера; секретов в ответе нет.
При отсутствии настроек ответ имеет вид
`{"enabled": false, "message": "AI не настроен. Основные функции доступны."}`.
Кнопка «Спросить» отключена. Прямой POST при выключенном AI возвращает
HTTP 503 с объяснением; успешный healthcheck приложения не означает,
что AI включён или провайдер доступен.

`POST /api/assistant/interpret` принимает `application/json`:

```json
{
  "question": "Покажи карточку участника 1",
  "context": {"selected": "1", "seeds": []},
  "history": []
}
```

`1` — вымышленный пример контракта; на датасете кейса такой выбранный gid
не пройдёт проверку. Для реального запроса нужен gid из `analysis.json`;
при отсутствии выбранного участника передайте `"selected": ""`.
Все gid — строки. История состоит из предыдущих
вопросов, не из заметок или вычисленных фактов. Ограничения: вопрос ≤2000
символов, история ≤6 вопросов по ≤2000 символов, до 5 исходных клиентов,
HTTP body ≤64 KiB, до двух одновременных запросов к провайдеру.

Успешный ответ содержит `operations` с 1–3 операциями:

| type | Аргументы | Результат в браузере |
|---|---|---|
| `node` | `gid` | Роль, приоритет, основание и следующий запрос |
| `common` | `seeds` из 2–5 различных исходных gid | Общая достижимость, первые 10 по приоритету и переход к полному списку |
| `route` | `source`, `target` | Путь с учётом дат; если его нет — доступный структурный путь |
| `sensitivity` | `gid` | Три сценария роли и их причины |

Вместо операций допускается `clarification`: `missing_context` или `unsupported`.
Текст уточнения формирует приложение. Все операции проверяются целиком до
исполнения: только разрешённые поля, существующие gid, корректные исходные
клиенты. Даже существующий gid отклоняется, если он отсутствовал в вопросе,
истории и выбранном контексте. При ошибке возвращаются HTTP-статус и `{error}`
без тела ответа провайдера и реквизитов доступа.

## Приватность и отказы

В Alem передаются системная инструкция, вопрос, контекст gid и до шести
предыдущих вопросов. Полный граф, операции, заметки и решения не передаются.
История существует только в памяти вкладки. Сервер не пишет запросы и ответы
в обычные логи; UI не получает ключ или URL провайдера. POST проверяет локальный
Host, Origin и Fetch Metadata, не включает CORS и не принимает другие форматы.

Сетевое ожидание провайдера ограничено 60 секундами; браузер прекращает ожидание
через 65 секунд. Отмена браузером не гарантирует прекращения уже отправленного
запроса в Alem. Автоматических повторов нет. Недоступность, отказ авторизации,
лимит, тайм-аут и некорректный JSON показываются как ошибки с возможностью повтора.
Основные вычисления, ручной поиск и досье работают без модели.

## Проверка

pytest проверяет запросы, операции, ограничения, ошибки провайдера и HTTP-границу.
Playwright подменяет только API ассистента, а карточки рассчитывает на реальном
`analysis.json`. В живом smoke-test использовались реальные настройки `.env`,
но только вымышленный участник `1`, без данных кейса. Текущие результаты —
в [VERIFICATION.md](VERIFICATION.md).

Ты — агент реализации проекта HackAlem «Граф денег». Твоя задача — написать
и проверить работающее решение, а не ограничиться планом или каркасом.
Общайся с пользователем на русском.

Сначала прочитай:

1. Инструкции AGENTS.md, переданные в сессии, и применимые инструкции репозитория.
2. `TECH_HANDOFF.md` — основной технический контракт и требования к Docker.
3. `PLAN.md` — порядок реализации и ограничения аналитики.
4. PDF с ТЗ в `case/`, `case/README.md` и `case/starter/README.md`.
5. `case/starter/starter.py` и его зависимости. Перед изменениями проверь
   состояние Git, сохрани существующие пользовательские изменения.

PDF определяет обязательные результаты кейса; TECH_HANDOFF уточняет
техническую реализацию и обязательный запуск через Docker Compose.
При существенном конфликте требований уточни его, не выбирай молча.

Реализуй решение последовательно:

1. Запусти starter, проверь Parquet и профилируй данные. Устрани неполноту
   валидации и включи изолированные узлы в граф. Развивай существующий
   пайплайн, не создавай параллельный расчёт с дублирующей логикой.
2. Реализуй признаки, объяснимые правила ролей, кластеры и приоритеты.
   Выбирай пороги по распределениям, сохраняй их в config и документируй.
   Не хардкодь gid и готовые ответы. Учитывай обрыв на depth=4, неполные
   входящие seed и остальные ограничения выборки. Каждый вывод — гипотеза.
3. Сформируй три CSV по ТЗ и единый `analysis.json` по TECH_HANDOFF.
   Все 2 248 узлов должны присутствовать, обязательные поля заполнены,
   evidence содержит числа. В браузер передавай gid строками.
4. Сделай React + TypeScript + Vite интерфейс с Cytoscape.js: таблица
   приоритетов, поиск любого gid, карточка и направленный граф окружения,
   фильтры и скачивание CSV. Используй реальные результаты Python.
   Реализуй загрузку, ошибки, пустые результаты и изолированные узлы.
5. Добавь Dockerfile, compose.yaml и .dockerignore. Сборка UI и установка
   Python-зависимостей происходят в Docker, расчёт — автоматически при
   старте. Один сервис app публикует http://localhost:8080. После сборки
   приложение работает без внешних API и CDN. Зафиксируй зависимости.
6. Проверь результат, обнови корневой README, подготовь диаграмму решения
   и короткий сценарий демо. Коммить успешно проверенные логические блоки
   по правилам AGENTS.md.

Главный критерий приёмки: из свежей копии репозитория пользователь выполняет
следующие команды и получает готовый интерактивный проект:

```sh
docker compose up -d --build --wait --wait-timeout 360
firefox http://localhost:8080
```

Обычный `docker compose up -d --build` тоже должен работать; до открытия
интерфейса пользователь дожидается готовности. Firefox — пример браузера.
На хосте не требуются Python, Node.js, uv, ручные команды расчёта или .env.
Healthcheck отражает готовность UI и валидных результатов текущего запуска.

До завершения:

- Проверь аналитические граничные случаи, схемы CSV/JSON, диапазоны скоров,
  согласованность кластеров и топа, повторяемость результатов.
- Замерь полный расчёт от Parquet до результатов: менее пяти минут,
  отдельно от загрузки зависимостей и сборки образа.
- Выполни проверки Python, TypeScript и production build.
- Проверь Compose из свежей копии без локальных окружений и старых
  результатов. Проверь перезапуск и явный отказ при ошибке данных.
- Через Playwright проверь поиск gid, таблицу, карточку, связи, изолят,
  неизвестный gid и скачивание CSV на реальном контейнерном приложении.
  Закрой браузер после проверки.

Не добавляй обязательную LLM-зависимость, внешнее обогащение, БД, очередь
или отдельный API без необходимости. Не оставляй заглушки вместо
обязательных функций. Рутинные технические решения принимай самостоятельно
в рамках документов. Не заявляй проверки, которые не выполнялись.

В финале сообщи: что реализовано, точные команды запуска и остановки,
результаты проверок и замер времени, известные ограничения. Если окружение
не позволило проверить Docker или браузер, явно укажи это; не называй
контейнерный запуск проверенным.
